# Account-Level HUFI Agent Foundation

This repository is the lightweight public standards source for `passaondigital` projects.

For substantial project work:
1. read `docs/00_UNIVERSAL_PROJECT_STANDARD.md`
2. read `docs/01_PROJECT_BOOTSTRAP.md` when starting/resuming a project
3. read `docs/02_AGENT_RELEASE_STANDARD.md` before release or when claiming completion
4. prefer local project `00_START_HERE` / `PROJECT_MANIFEST` for project-specific truth
5. verify live/runtime truth before mutation
6. use UNKNOWN rather than guessing

Authorized internal HUFI agents may load deeper reusable skills from the private `passaondigital/hufi-factory` repository.

## HUFI Account Project Standard

These project-wide rules supplement, but do not replace, stricter project-specific instructions above.

Before substantial work:
1. Recover the current project truth before mutation.
2. Prefer local `00_START_HERE.md`, `PROJECT_MANIFEST.md`, `STATUS.md`, `DEPLOYMENT.md` and verified runtime facts for project-specific state.
3. Apply: **DISCOVER → VERIFY → REUSE → IMPLEMENT → TEST → VERIFY LIVE → DOCUMENT**.
4. Use only: `IDEA / PLANNED / FOUNDATION / BUILT / TESTED / STAGING / PRODUCTION / PARTIAL / BLOCKED / UNKNOWN`.
5. `NOT TESTED` is never `PASS`; `BUILT` is not `PRODUCTION`.
6. Reuse before adding a framework, service, model, database or parallel implementation.
7. Keep deterministic authority for identity, permissions, money, billing state and destructive actions.
8. Never expose raw secrets in Git, prompts, normal docs, memory or work evidence.
9. Before production require appropriate rollback, tests, security checks, staging/smoke verification and post-deploy smoke.
10. After substantial work update durable status so a future agent can continue without the old chat.

Public foundation:
- `passaondigital/hufi-architecture-board/docs/00_UNIVERSAL_PROJECT_STANDARD.md`
- `passaondigital/hufi-architecture-board/docs/01_PROJECT_BOOTSTRAP.md`

If central sources cannot be accessed, the embedded rules here still apply.
